# The tricot command

Back to the [README](../README.md).

## Commands

`tricot status` shows where it runs, `tricot stop` stops it, `tricot connect [claude|codex|pi|gemini|grok]` connects an agent by running its own command, after asking (`--print` only shows it; [below](#connecting-an-agent)), `tricot connect [omp|opencode|goose|hermes|mcp-json|url]` shows what to add for the others, `tricot claude` (or `codex`, `opencode`, `pi`, `omp`) starts the board and the agent together (below), `tricot --background` keeps it running after the terminal closes, and `tricot update` updates it (see [Updates](configuration.md#updates)). It uses one server per data folder (a `server.lock` inside it), so a second `tricot` reuses the first. `tricot --help` lists the commands and the options that go with starting the board, and `tricot <command> --help` says what that command does and shows only the options it takes (`tricot connect --help` has `--print` and `--yes`, `tricot steps --help` has `--agent` and `--project`). A command Tricot doesn't know is answered with the closest one: `tricot stats` says `Did you mean "status"?` When another `tricot` on your `PATH` is another version, that message names it ([below](#updating-and-removing-it)).

### Stopping the board

`tricot stop` asks the running board to stop itself, over HTTP, and ends it with a signal only when that can't be done: the board then saves its boards and lets go of its data folder as it ends. Asking is a person's to do, so it needs one of your seats, like `tricot update` ([below](#letting-a-browser-act-for-you)). On macOS and Linux a terminal that isn't let in yet goes straight to the signal, which also stops the board gently. On Windows a signal ends a program at once, so `tricot stop` shows a code and waits a minute for you to allow this terminal in your browser; without that it ends Tricot at once, and the last moments of work may not be saved.

### Letting a browser act for you

What is consequential (answering an agent's request, approving a commit, deciding, marking a card ready and the like) is done only from a browser or terminal you let in, once each ([Browsers and terminals you let in](configuration.md#browsers-and-terminals-you-let-in)). When `tricot` runs the board in the foreground in a terminal, that terminal asks when a browser wants to act for you: "A browser wants to act for you (Chrome on macOS, code 4271). Allow?", with **Yes** and **No** beside it and No marked. Check that the browser shows the same code; **y** lets it in, **n** or Enter says no, and ←→ move the mark first, if you would rather choose. It asks only then, reads keys only while it asks, and Ctrl+C still stops Tricot. It answers the very first browser, and having let that one in, is let in with it until Tricot stops; after that it answers every browser that asks.

For a board running in the background (`tricot -d`) or started elsewhere, `tricot access` does the same: it lists your browsers and terminals and those waiting, with their codes, and asks Yes or No for each waiting one, the same way. It answers the first browser as that terminal does; later ones once it is let in itself, from a browser you've already let in, which it asks for with a code. `tricot access revoke`, with Tricot stopped on that data folder, asks "Remove every browser and terminal you've let in?" (Yes or No, No marked) and lets them all go: the next browser is then let in as the first one was.

## Starting an agent with the board

`tricot claude`, `tricot codex`, `tricot opencode`, `tricot pi` and `tricot omp` start the board in the background (or find the one already running on the same data folder, as `tricot` does), ask which board to work on, open it in the browser (not with `--no-open`), and then start the agent in this terminal, with the strip and the Tricot tab ([below](#several-agents-in-one-terminal)). The agent gets the board for this session only and its own settings aren't touched. Its first message tells it to use that board and start listening. When the agent quits, the command returns its exit code, and a board it started stops with it. If another `tricot claude` (or `codex`, `opencode`, `pi`, `omp`) is using that board, it keeps running until the last of them quits, and a browser tab doesn't count. If the command is killed outright or its terminal crashes, the board notices that no agent command is there any more, and stops by itself within half a minute. A board you started with `tricot` or `tricot start` or `tricot --background` keeps running when the agent quits, as before. `tricot stop` stops any board. The first time, it also asks about [live steps](#live-steps), as `tricot` does.

Without `--board <id>`, Tricot lists the boards updated most recently, with how long ago each was. Move with the arrow keys, pick with Enter, and cancel with Esc or Ctrl+C, which starts nothing. "＋ New board…" makes one, named after the folder unless you change it. The board picked in a folder starts highlighted there next time, because Tricot remembers it in its data folder (`folder-boards.json`), never in the project. Without a terminal, as in a script, it stops and asks for `--board`.

`--name` sets the agent's name on the board, `--model` and `--effort` what it starts on ([below](#the-model-and-thinking-level-an-agent-starts-on)), and anything after `--` goes to the agent (`tricot claude -- --strict-mcp-config`). Each agent is connected through its own per-session option, from its own docs:

- **Claude Code:** `--mcp-config` with the server as JSON, and the token, when the board needs one, as its `Authorization` header. If you already have a server named `tricot` in Claude Code's settings, its docs don't say which of the two it uses, so the session uses one or the other. Add `-- --strict-mcp-config` to use this one alone, which also leaves out your other MCP servers for that session. `--allowedTools mcp__tricot__*` lets Tricot's own tools run without asking, and `--settings` gives the session Tricot's hooks: its permission prompts come to the board, and its [live steps](#live-steps) too if you said yes to them. Whichever of those hooks your own `~/.claude/settings.json` runs already is left out, so nothing runs twice. The output says where approvals go.
- **Codex:** `-c mcp_servers.tricot.url=…` overrides, which rank above every config file. With a token, `bearer_token_env_var` names `TRICOT_TOKEN`, which is set in Codex's environment only. `default_tools_approval_mode="approve"` lets Tricot's own tools run without asking; your own `tricot` entry's other settings still apply. Codex takes hooks only from its settings, so its permission prompts come to the board once its live steps are on (`tricot steps on --agent codex`), and the output says which.
- **OpenCode:** the entry in `OPENCODE_CONFIG_CONTENT`, in its environment only, which OpenCode merges over its global and project config, and `--prompt` for the first message.
- **Pi:** `-e` loads a small extension for this run, which adds the board as an MCP server for the session (`pi.registerMcpServer`). The extension is a file in a private folder made for the session (in the system's temporary folder, with the board's address and nothing else in it) and removed when Pi ends; if Tricot is killed outright it stays, and the next `tricot` agent command removes such folders once they are a day old. Your `~/.pi` folder isn't touched, and Pi's sign-in, models and sessions are where they were. With a token, the entry reads it from `TRICOT_TOKEN`, set in Pi's environment only. A server named `tricot` in your own `~/.pi/agent/mcp.json` (from `tricot connect pi`) takes precedence over the session's, as Pi's docs say. Pi reaches the board's tools through its `codemode` tool, as when you connect it by hand.
- **OMP:** `-e` loads an extension folder for this run, and OMP reads the MCP servers a `.mcp.json` in it holds. The folder is private, made for the session, holds that one file and is removed when OMP ends (one left by a Tricot killed outright is swept like Pi's); your `~/.omp` folder isn't touched, and OMP's sign-in, models and sessions are where they were. With a token, the entry reads it from `TRICOT_TOKEN`, set in OMP's environment only. The session's entry ranks below one named `tricot` in your own `~/.omp/agent/mcp.json` (from `tricot connect omp`) and above the Claude Code, Codex and Gemini CLI files OMP also reads, so it shows on the board as "OMP" and not as "Claude".

If the agent isn't on your `PATH`, Tricot says how to install it and starts nothing, not even the board. Gemini CLI has no per-session option that leaves its settings alone (it adds a server only from a settings file), so `tricot gemini` prints how to connect it (as `tricot connect --print` does) and starts nothing. The same goes for `tricot goose` and `tricot hermes`: Goose's flag for one session names the server after the address and can't send the board's token, and Hermes Agent adds a server only to its config file. Grok Build is the same: its interactive mode reads MCP servers only from its config files and installed plugins, so `tricot grok` prints how to connect it and starts nothing.

### The model and thinking level an agent starts on

Each agent starts on the model and thinking level set for it in its panel (open it from the menu under your name): a chip beside its name says it ("Opus · high"), or "Its own settings" when nothing is set, and opens a list of both, with a field for a model of your own. It is the same on every board, kept in the data folder (`agent-rules.json`) rather than in a board, and only you change it, from a browser you let in; agents can't. Default passes nothing, so the agent's own settings apply, as before. A change takes effect the next time Tricot starts the agent, and the line under its name says what it runs on now: "Running on Opus · high", or "On Opus · high till it restarts". An agent you started yourself says nothing there.

`--model` and `--effort` after an agent's name stand in for its rule for that run, one by one: `tricot claude --model opus --effort high codex --model gpt-6.1-sol`. With one agent they can come anywhere; with several, one before every agent's name is refused. `--effort` is Tricot's one name for the thinking level, given to each agent in its own words, and refused for one that has none Tricot can set. A value that starts with `-` or holds a control character is refused, and each value is its own argument, never through a shell.

| Agent | Model | Thinking level |
| --- | --- | --- |
| Claude Code | `--model` (`opus`, `sonnet`, `haiku`, `fable`, or a full name) | `--effort`: low, medium, high, xhigh, max |
| Codex | `--model` | `-c model_reasoning_effort="…"`: low, medium, high, xhigh, max, ultra |
| Pi | `--model` (a pattern it matches) | `--thinking`: off, minimal, low, medium, high, xhigh, max |
| OMP | `--model=` (a pattern it matches) | `--thinking=`: off, minimal, low, medium, high, xhigh, max, auto |
| OpenCode | `--model` (`provider/model`) | none |

The strip at the bottom of the terminal says what each was started on after its name (`○ 1 Claude · Opus high · Running npm test`) while the line has room for it and the keys.

For one message, tag the agent instead: `@Claude:opus:high` asks Claude to do that message's work on Opus at high thinking, and its session and its rule stay as they are. Either part can be left out (`@Claude:opus`, `@Claude::high`). It is still a mention of Claude in every way (who hears it, delivery, the chips, notifications); the agent's updates add "asks you to do this on opus at high thinking: hand the work to a subagent on that model and thinking level, and keep your own session as it is". Only Claude Code can do this for now, through a subagent (its Agent tool takes `opus`, `sonnet`, `haiku` or `fable`, so a full name goes by its family: `claude-opus-4-5` is `opus`). The other agents use their own model and thinking for the message, and Tricot says so before you send it; the message still goes. A thinking level must be one of the agent's own, and a model is refused as on the command line; a model whose name holds a colon can't be tagged. A tag goes only on an agent's mention: `@Sam:later` and `sam@example.com` read as they always have.

### Several agents in one terminal

`tricot claude codex` (any of `claude`, `codex`, `opencode`, `pi` and `omp`, in any order) starts the board and asks which board once, then starts each agent exactly as above, with its own name on the board, all in this terminal. One tab shows at a time, and a strip on the bottom line lists them all, each agent with what it is doing: its latest step on the board, "waiting for your OK" when its request for permission waits on the board, "wants you" when a hidden one rings its bell, "listening on the board", or, without live steps, whether it is drawing. One that quits says "ended", with its exit code when that isn't 0, and keeps its place. One you stop from the Tricot tab leaves the strip at once, and those after it move up a number.

The first tab is Tricot's own, and it opens on the chat: one stream of every conversation on the board, oldest at the top and scrolled to the latest. It holds every thread message, every comment in a task's or a decision's discussion (backlog cards included), and every comment on a pinned part of a canvas; progress notes, activity and requests for approval stay in **/status**. Each message says who wrote it, where it belongs and when: "in" a thread (with its lens before the title unless it is General), "on T17" or "on #7" for a card, and "on the board" for the board context, with the part a comment is about after it. New messages and comments arrive live, as on the page; **↑ ↓**, Page Up, Page Down, Home and End scroll while nothing is typed, and a stream scrolled up stays where it is, the row above the line saying how many newer messages are below. **Enter** takes it back to the latest: on an empty line that is all it does, and with something typed it sends it and goes there.

Under the stream, what you type answers the latest message from someone else, where it is: a reply in its thread, a comment in its task's or decision's discussion, or a reply about its pinned part, sent as you and shown at once. The row under the line says where it goes and who hears it, for example "to T19 Stopped agents leave the strip, the latest · Claude hears it". A message that arrives while you type doesn't move it; once the line is empty again, it follows the latest. When nothing in the stream is from someone else, the line starts a thread.

To send elsewhere, begin with **@** and a name to start a new thread aimed at that agent (it is then picked, as from the threads' panel below, and **Esc** brings you back to the whole stream), or with **>** and a place: **>T19** a task, **>#7** a decision, or **>** and part of a thread's title. **Tab** completes the name or the place, listing each place with its title; a place the board doesn't have says why and sends nothing. A **>** followed by a space is plain text. With nothing typed, **Tab** chooses an earlier message to answer, marked ❯: each **Tab** (or **↑**) goes one further back and **Shift+Tab** (or **↓**) one later, **1 2 3** leave 👍 👎 👀 on it or take yours back, and what you type answers it. A thread whose latest message you have read in the stream no longer waits on you in **/threads**. Letters such as **y**, **n**, **x** and **q** are text while you chat: they answer requests or stop agents only in the status view.

After an agent's name, **:** starts a tag for that one message ([above](#the-model-and-thinking-level-an-agent-starts-on)): the row above the line lists the agent's models and **Tab** writes each in turn, as it does a name (a colon typed just after a name **Tab** wrote takes the place of its space), and after a second **:** its thinking levels. Any other model can be typed. The row under the line adds what the message runs on ("to Claude, on Opus at high thinking · Claude is listening: this is seen at once."), or, in the alert colour, that the agent can't switch models for one message and will use its own, or what is wrong with the tag.

Type **/** to see local commands alongside agent skills. Local commands say “Tricot command”; an agent skill names its agent and completes to **@Agent /skill**. Use **Tab** or the arrow keys to choose, then **Enter**. A command on its own navigates here; a message such as **@Claude /status** still goes to that agent.

- **/status** opens the agents, approval requests and board activity.
- **/threads** opens the threads in a panel beside the stream, with what waits on you first.
- **/new** goes back to the stream, with the line starting a new thread; **Esc** goes back to answering the latest.

In the status view or the threads' panel, **/** opens a navigation line without changing an unsent message. **Esc** cancels that line; in status, **Esc** returns to chat. In the stream, **Esc** clears what you typed; with nothing typed it goes back from a message chosen to the latest, then from a thread picked to the whole stream, and then opens the threads' panel. Requests for approval stay visible while you chat, with **/status** beside them.

The TRICOT wordmark stays at the top, with the board's title and address beside it. It knits up once in under a second; any key finishes the animation and still acts as typed. `TRICOT_NO_ANIMATION=1` shows it whole at once, and a small window uses a one-line header. Switching tabs does not replay the animation.

The threads' panel lists what waits on you first (● waiting on you, • replies you haven't seen), then the rest by when they were last active, and the quiet finished ones under Earlier, with **Show N more**. From about 100 columns it sits at the stream's right, about a third of the width, the stream still in view beside it; in a narrower window it covers the stream. While it is open, **↑ ↓** move through its threads and **Enter** picks one: the stream then shows only that thread's messages, scrolled to its latest, under a row that says so ("Only Picker spacing · Esc for everything"), and the line answers it, the row under it saying who hears it ("to Picker spacing · Claude hears it"). An **@** at the start of the line is then a mention in the thread, not a new one. **Enter** sends your reply as you; a refused send keeps your text and says why. With nothing typed, **Tab** chooses one of the thread's messages from someone else, **1 2 3** leave 👍 👎 👀 on it or take yours back, and **Ctrl+L** sets the thread's lens. **Esc** goes back a step at a time: from the thread picked to the whole stream, the panel still open with that thread highlighted, and then closes the panel (back to the status view when **t** opened it there). In a narrow window a thread picked takes the whole window, and **Esc** brings the panel back before closing it. In the panel, **n** starts a new thread as **/new** does, and **l** (or **Ctrl+L**) sets the highlighted thread's lens, the lenses listed in the panel's place. The panel stays as you left it while you look at an agent's tab or at **/status**.

In **/status**, **y** allows the selected request, **s** allows it for the session where offered, and **n** denies it after an optional reason. **← →** choose an answer, **Enter** confirms it, and **↑ ↓** choose another request. The default is Deny, so a stray Enter never allows one. **o** opens the board in your browser, **t** opens the chat with the threads' panel, **a** adds an agent, **x** asks which agent to stop and confirms with No selected (the agent leaves the strip and the list at once, which makes room to add another: one terminal holds nine), and **q** quits. A request answered here and on the page can cross: the first answer wins. When a request arrives while an agent's tab shows, the strip tells you. Once every agent has ended, Tricot's tab stays until you quit or add one.

In the threads' panel, **x** asks to delete the highlighted thread, in the panel's place, with **No** selected. Choose with **← →** and confirm with **Enter**, or answer with **y** or **n**; **Esc** and **Ctrl+C** cancel. **u** undoes your latest deletion in this terminal, including when the panel is empty. Tasks and decisions made in the thread stay.

**Ctrl+\\** shows the next tab, and the one after it each time you press it again, round the strip from the last tab to the first. Ctrl+\\ is Tricot's alone: it never reaches an agent. Within a second after a press, **0** shows the Tricot tab and a number shows that agent, **q** quits (every agent is closed, as closing the window would), **[** scrolls back through the history of an agent that has one (of the tab you were on before the first press). The arrow keys go to the agent as usual. Ctrl+Z does nothing here, as an agent stopped in a hidden terminal couldn't be brought back.

A click on the strip shows the tab you click, from any tab. For this, Tricot keeps your terminal reporting the mouse all the time, so a plain drag no longer selects text: hold **Shift** while you drag (**Option** in iTerm2). An agent that turned the mouse on itself still gets what it asked for above the strip: its clicks, drags and wheel. Otherwise clicks above the strip do nothing, and the wheel scrolls: the chat in the Tricot tab, an agent's history as **[** does (scrolling back down to the bottom returns to the agent), or, for an agent that draws its own screen, ↑ and ↓ as your terminal would send them.

Each agent runs in a pseudo-terminal of its own, made with the Perl that ships with macOS (then Python's `pty`, then the `script` command), so nothing is installed. Hidden agents keep running and get their startup questions answered; your terminal's input settings follow the agent showing (but for the mouse, above), and a resize reaches all of them. Claude Code runs in its full-screen renderer here. When you quit, the terminal is put back, the board stops if this command started it and no other agent command needs it (as above), and the command returns the first exit code other than 0, in the order the agents were named and then added (an agent still running when you quit, or stopped from the Tricot tab, was closed, not failed).

To answer from its tab, the terminal is let in once, as a browser is (see [Browsers and terminals you let in](configuration.md#browsers-and-terminals-you-let-in)). Until then the tab shows that an agent is waiting, but not what it asks, and **y** asks to let the terminal answer: your browser shows "Let this terminal answer for you?" with the code the tab shows, and one click there lets it in until it closes. The tab registers with the running board as it starts, and makes the key it signs with; it keeps both in memory only (never in a file, an environment variable or an argument, so the agents it starts never see them) and lets go of them as it ends. When a browser asks to act for you, the tab asks too: "A browser wants to act for you (Chrome on macOS, code 4271). Allow? [y/N]". **y** allows it, **n** or Enter denies it, Esc leaves it for the board; while no browser has ever been let in, any Tricot terminal answers it, once, and is let in with it.

It needs a terminal, and doesn't work on Windows yet.

One agent runs this way too: `tricot claude` shows Claude Code with the strip at the bottom and the Tricot tab beside it, so the process view is there with one agent as with several. `--name` and words after `--` name one agent, so they work with one (`tricot claude --name Reviewer -- --strict-mcp-config`), and are refused with several; `--model` and `--effort` go after each agent's name instead. Where the strip can't run (Windows, no terminal, or no way to give the agent a terminal of its own), one agent runs on its own in this terminal, as [above](#starting-an-agent-with-the-board), and says why when your terminal could have had it; several agents are refused there. Gemini CLI can't be started this way either, as above.

## Connecting an agent

`tricot connect claude` connects Claude Code, and `codex`, `pi`, `gemini` and `grok` connect theirs: Tricot shows the agent's own command, says which of its settings it changes (a server named `tricot`, in `~/.claude.json`, `~/.codex/config.toml`, `~/.pi/agent/mcp.json`, `~/.gemini/settings.json` or `~/.grok/config.toml`, for every session), asks whether to run it (Yes or No, No marked), runs it, and says whether it worked. Before it asks, it reads what the agent already has under the name `tricot` (`claude mcp get tricot`, `codex mcp get tricot`; Pi, Gemini CLI and Grok Build have no such command, so for them Tricot only adds). When that is already this board's address, it says "Claude Code is already connected to this board. Nothing to do." and runs nothing. When it is another address (another port, or another `--name`), it says what it found and asks once whether to replace it, running the agent's `remove` and then its `add`; it never replaces with `--yes` or without a terminal, and says the commands to run yourself. If the agent refuses, its own message is shown and the exit code is 1. `--yes` skips the question and still shows the command.

`--print` shows the command and runs nothing: for scripts, and for an agent that isn't installed on this computer. Tricot runs nothing either, and prints the command the same way, when there is no terminal to ask in and no `--yes`, or when the agent isn't on your `PATH`, and says what to do. It runs the command without a shell, with 30 seconds to finish. `omp`, `opencode`, `goose`, `hermes`, `mcp-json` and `url` are a file to edit or an address (for Goose and Hermes Agent, a YAML file: `~/.config/goose/config.yaml` and `~/.hermes/config.yaml`), so `tricot connect` only shows those. `tricot connect` alone lists every way.

The same by hand, for Claude Code (or any MCP client that speaks Streamable HTTP, by its address):

```sh
claude mcp add --scope user --transport http tricot http://127.0.0.1:4545/mcp
```

Without `--scope user`, Claude Code keeps the server for the one folder you ran the command in.

Add `?agent=Name` to the URL to label an agent on the board, e.g. when several agents share one board. Without it, the MCP client's own name is used.

## Live steps

The first `tricot` in a terminal finds the agents on your machine (Claude Code, Codex, Pi, OMP, Gemini CLI, OpenCode, Goose, Hermes Agent, Grok Build) and asks once whether to show their steps live on your boards ("Reading src/app.ts", "Running npm test" on the card each one works on). It lists the files it would write for each agent; a yes adds a small hook to each agent's own settings, for every project, and a no is remembered too (in the data folder), so it isn't asked again. It never asks without a terminal, in CI, or with `--no-ask`; `--verbose` shows every line first. `tricot steps` shows where each agent stands, and `tricot steps on|off [--agent claude|codex|pi|omp|gemini|opencode|goose|hermes|grok]` turns them on or off later, again showing the lines and asking first (`--yes` skips the question). Each agent's panel in Tricot has the same as a "Live steps" switch, which shows the exact files and lines before it writes anything; agents can't turn it on or off themselves. Codex runs a new hook only once you trust it in its `/hooks`, which Tricot says when it sets it up; Hermes Agent asks you to approve each hook the first time it runs it (`hermes hooks list` shows which are approved). Goose's steps are a plugin of its own, `~/.agents/plugins/tricot-steps/`, whose hooks Goose runs with `sh` (on Windows, from the bash that comes with Git for Windows). Hermes keeps its hooks in `config.yaml`, which Tricot doesn't parse: it adds one `hooks:` section between two comment lines, changes nothing else in the file, and stops, saying so, when the file already has a `hooks:` section of its own or isn't there yet (Hermes makes it the first time it runs). None of this touches a project's own settings: a project that still has its own hook, from `tricot steps on --agent claude --project`, keeps it, and each step still shows once (the board keeps one of the two copies).

Live steps also pass on each agent's usage, for the Usage section of its panel, and only as numbers. Claude Code tells its plan usage only to its status line, so turning Claude's live steps on also sets `statusLine` in `~/.claude/settings.json` to Tricot's `tricot-usage.mjs`: it keeps from Claude Code's status-line input only the 5-hour and weekly windows (how much is used, when each resets), the session's cost and how full its context is, sends those to Tricot, then runs your own status line with the same input and prints what it prints. Your own status line is kept in `~/.claude/hooks/tricot-usage.json`, and turning live steps off puts it back exactly (or none, if you had none). If you set a status line yourself later (`/statusline`), Tricot leaves it alone and the panel says plan usage stopped. Codex's hook, at the end of each turn, reads the last 256 KB of Codex's own session file and sends only its plan windows, plan and token totals. Pi, OMP and OpenCode send their session's tokens and cost at the end of each turn; Gemini CLI, Goose, Hermes Agent and Grok Build share nothing Tricot can reach. Nothing reads a login or asks a usage API, and Tricot keeps the numbers in memory only. To stop it, turn live steps off for that agent (`tricot steps off --agent claude`, or the switch in its panel).

With live steps on, Claude Code's and Codex's permission prompts come to the board too: when one asks to run something, its request waits on the card it is working on, as a toast wherever you are in Tricot, and on the chat bar, with Allow, Allow for this session (Claude Code only) and Deny, where you can say why for the agent to read. Allow for this session also allows what Claude Code suggested with the request, for the rest of the session, and the card lists each rule, mode and folder that adds; it is offered only when the card can list all of them in full. What it asks to run shows exactly as it sent it. A background tab says so in its title ("⏸ Claude needs you"), with a system notification if you turned them on. A small hook, `tricot-approve.mjs`, beside the steps hook, sends the request to Tricot and waits for your answer, for as long as you take; it never answers on its own, and when Tricot isn't running (it tries once more, so the terminal asks within a second) or anything goes wrong, the agent asks in the terminal as usual. It believes only the Tricot that holds your data folder (`~/.tricot`, or `TRICOT_DATA_DIR` in the agent's environment): each start of Tricot writes a random secret in its `server.lock`, which only your account can read, and the hook sends a fresh random challenge with everything it asks and prints an answer only when the board proves it holds that secret (an HMAC of the challenge, the request and the answer). Another program that takes the port while Tricot restarts has no secret, so it gets no answer through and never sees what the agent asked to run; a Tricot from before this check, which writes no secret, and a board on another computer, where the hook has no lock to read, make the terminal ask. It works the same on Windows, which has no `lsof`. A program running as you can read the secret too, so this stops a stand-in server, not a determined one. If the agent stops waiting (the prompt answered in the terminal, or the session ended), the request leaves the board. Only a person answers, from a browser or Tricot terminal they let in, on this computer: no MCP tool can, and a page that isn't let in sees who waits, not what they ask. Turning live steps off takes the approval hook out with the rest.

`tricot steps on --agent claude --project`, run in a project, offers to add a Claude Code hook to its `.claude/settings.json` (it shows the JSON and asks first): the card Claude works on then shows what it is doing, one line per step ("Running npm test"), and a command or subagent that takes a while stays live until it ends ("Ran npm test (42 s)"). The same line shows under a message you're waiting on Claude to answer, and on the project's row on the home page. The hook sends no file contents or command output, runs in the background and does nothing when Tricot isn't running. With `--narration` it also sends the first line of each message Claude writes in the terminal (never its thinking); that is off unless you ask for it. `tricot steps off --agent claude --project` takes it out again.

## Updating and removing it

The same `npm install -g tricot` updates it (`brew upgrade tricotstudio/tap/tricot` with Homebrew), and `npm uninstall -g tricot` removes the command; your boards stay in `~/.tricot` either way. To try it once without installing, `npx tricot` runs the same command.

Two installs can exist at once, say an old `npm install -g tricot` under nvm and Homebrew's, and the first `tricot` on your `PATH` is the one that runs, whichever is newer. `which -a tricot` (`where tricot` on Windows) lists them: remove the one you don't want, with `npm uninstall -g tricot` or `brew uninstall tricotstudio/tap/tricot`. `tricot --version` is the version of the command you ran, so `tricot update` says when it is older than the running board ("This command is 0.1.1 but the board runs 0.1.4."), lists each `tricot` on your `PATH` and the command to remove the old one; it never removes anything itself.
