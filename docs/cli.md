# The tricot command

Back to the [README](../README.md).

## Commands

`tricot status` shows where it runs, `tricot stop` stops it, `tricot connect [claude|codex|pi|gemini]` connects an agent by running its own command, after asking (`--print` only shows it; [below](#connecting-an-agent)), `tricot connect [omp|opencode|mcp-json|url]` shows what to add for the others, `tricot claude` (or `codex`, `opencode`, `pi`, `omp`) starts the board and the agent together (below), `tricot --background` keeps it running after the terminal closes, and `tricot update` updates it (see [Updates](configuration.md#updates)). It uses one server per data folder (a `server.lock` inside it), so a second `tricot` reuses the first. `tricot --help` lists the commands and the options that go with starting the board, and `tricot <command> --help` says what that command does and shows only the options it takes (`tricot connect --help` has `--print` and `--yes`, `tricot steps --help` has `--agent` and `--project`). A command Tricot doesn't know is answered with the closest one: `tricot stats` says `Did you mean "status"?`.

### Stopping the board

`tricot stop` asks the running board to stop itself, over HTTP, and ends it with a signal only when that can't be done: the board then saves its boards and lets go of its data folder as it ends. Asking is a person's to do, so it needs one of your seats, like `tricot update` ([below](#letting-a-browser-act-for-you)). On macOS and Linux a terminal that isn't let in yet goes straight to the signal, which also stops the board gently. On Windows a signal ends a program at once, so `tricot stop` shows a code and waits a minute for you to allow this terminal in your browser; without that it ends Tricot at once, and the last moments of work may not be saved.

### Letting a browser act for you

What is consequential (answering an agent's request, approving a commit, deciding, marking a card ready and the like) is done only from a browser or terminal you let in, once each ([Browsers and terminals you let in](configuration.md#browsers-and-terminals-you-let-in)). When `tricot` runs the board in the foreground in a terminal, that terminal asks when a browser wants to act for you: "A browser wants to act for you (Chrome on macOS, code 4271). Allow? [y/N]". Check that the browser shows the same code; **y** lets it in, **n** or Enter says no. It asks only then, reads one key, and Ctrl+C still stops Tricot. It answers the very first browser, and having let that one in, is let in with it until Tricot stops; after that it answers every browser that asks.

For a board running in the background (`tricot -d`) or started elsewhere, `tricot access` does the same: it lists your browsers and terminals and those waiting, with their codes, and asks y/N for each waiting one. It answers the first browser as that terminal does; later ones once it is let in itself, from a browser you've already let in, which it asks for with a code. `tricot access revoke`, with Tricot stopped on that data folder, asks "Remove every browser and terminal you've let in? [y/N]" and lets them all go: the next browser is then let in as the first one was.

## Starting an agent with the board

`tricot claude`, `tricot codex`, `tricot opencode`, `tricot pi` and `tricot omp` start the board in the background (or find the one already running on the same data folder, as `tricot` does), ask which board to work on, open it in the browser (not with `--no-open`), and then start the agent in this terminal, with the strip and the Tricot tab ([below](#several-agents-in-one-terminal)). The agent gets the board for this session only and its own settings aren't touched. Its first message tells it to use that board and start listening. When the agent quits, the command returns its exit code, and a board it started stops with it. If another `tricot claude` (or `codex`, `opencode`, `pi`, `omp`) is using that board, it keeps running until the last of them quits, and a browser tab doesn't count. If the command is killed outright or its terminal crashes, the board notices that no agent command is there any more, and stops by itself within half a minute. A board you started with `tricot` or `tricot start` or `tricot --background` keeps running when the agent quits, as before. `tricot stop` stops any board. The first time, it also asks about [live steps](#live-steps), as `tricot` does.

Without `--board <id>`, Tricot lists the boards updated most recently, with how long ago each was. Move with the arrow keys, pick with Enter, and cancel with Esc or Ctrl+C, which starts nothing. "＋ New board…" makes one, named after the folder unless you change it. The board picked in a folder starts highlighted there next time, because Tricot remembers it in its data folder (`folder-boards.json`), never in the project. Without a terminal, as in a script, it stops and asks for `--board`.

`--name` sets the agent's name on the board, and anything after `--` goes to the agent (`tricot claude -- --model opus`). Each agent is connected through its own per-session option, from its own docs:

- **Claude Code:** `--mcp-config` with the server as JSON, and the token, when the board needs one, as its `Authorization` header. If you already have a server named `tricot` in Claude Code's settings, its docs don't say which of the two it uses, so the session uses one or the other. Add `-- --strict-mcp-config` to use this one alone, which also leaves out your other MCP servers for that session. `--allowedTools mcp__tricot__*` lets Tricot's own tools run without asking, and `--settings` gives the session Tricot's hooks: its permission prompts come to the board, and its [live steps](#live-steps) too if you said yes to them. Whichever of those hooks your own `~/.claude/settings.json` runs already is left out, so nothing runs twice. The output says where approvals go.
- **Codex:** `-c mcp_servers.tricot.url=…` overrides, which rank above every config file. With a token, `bearer_token_env_var` names `TRICOT_TOKEN`, which is set in Codex's environment only. `default_tools_approval_mode="approve"` lets Tricot's own tools run without asking; your own `tricot` entry's other settings still apply. Codex takes hooks only from its settings, so its permission prompts come to the board once its live steps are on (`tricot steps on --agent codex`), and the output says which.
- **OpenCode:** the entry in `OPENCODE_CONFIG_CONTENT`, in its environment only, which OpenCode merges over its global and project config, and `--prompt` for the first message.
- **Pi:** `-e` loads a small extension for this run, which adds the board as an MCP server for the session (`pi.registerMcpServer`). The extension is a file in a private folder made for the session (in the system's temporary folder, with the board's address and nothing else in it) and removed when Pi ends; if Tricot is killed outright it stays, and the next `tricot` agent command removes such folders once they are a day old. Your `~/.pi` folder isn't touched, and Pi's sign-in, models and sessions are where they were. With a token, the entry reads it from `TRICOT_TOKEN`, set in Pi's environment only. A server named `tricot` in your own `~/.pi/agent/mcp.json` (from `tricot connect pi`) takes precedence over the session's, as Pi's docs say. Pi reaches the board's tools through its `codemode` tool, as when you connect it by hand.
- **OMP:** `-e` loads an extension folder for this run, and OMP reads the MCP servers a `.mcp.json` in it holds. The folder is private, made for the session, holds that one file and is removed when OMP ends (one left by a Tricot killed outright is swept like Pi's); your `~/.omp` folder isn't touched, and OMP's sign-in, models and sessions are where they were. With a token, the entry reads it from `TRICOT_TOKEN`, set in OMP's environment only. The session's entry ranks below one named `tricot` in your own `~/.omp/agent/mcp.json` (from `tricot connect omp`) and above the Claude Code, Codex and Gemini CLI files OMP also reads, so it shows on the board as "OMP" and not as "Claude".

If the agent isn't on your `PATH`, Tricot says how to install it and starts nothing, not even the board. Gemini CLI has no per-session option that leaves its settings alone (it adds a server only from a settings file), so `tricot gemini` prints how to connect it (as `tricot connect --print` does) and starts nothing.

### Several agents in one terminal

`tricot claude codex` (any of `claude`, `codex`, `opencode`, `pi` and `omp`, in any order) starts the board and asks which board once, then starts each agent exactly as above, with its own name on the board, all in this terminal. One tab shows at a time, and a strip on the bottom line lists them all, each agent with what it is doing: its latest step on the board, "waiting for your OK" when its request for permission waits on the board, "wants you" when a hidden one rings its bell, "listening on the board", or, without live steps, whether it is drawing. One that quits says "ended", with its exit code when that isn't 0.

The first tab is Tricot's own, and it shows first. It has the board and Tricot's address, each agent and what it is doing (and for how long), the requests for permission waiting from your agents, each with exactly what the agent sent, and the board's latest activity. Its keys: **y** allows the request, **s** allows it for the session (where that is offered), **n** denies it (type a reason for the agent first if you like, then Enter), and **↑ ↓** pick another when several wait; **o** opens the board in your browser, **a** lists every agent Tricot knows that isn't running (Claude Code, Codex, OpenCode, Gemini CLI, Pi, OMP) and adds the one you pick in a tab of its own (one that isn't installed says so, and one Tricot can't start for you yet says to connect it first, with the command), **x** stops one (it is hung up, after a **y**), and **q** quits. An answer from here and one from the board can cross: the first one wins, and the other side is told who answered. When a request comes in while an agent shows, the strip says so, and for a moment "Ctrl+\\ 0 to answer". With every agent ended, the Tricot tab stays until you quit or add one.

**Ctrl+\\** shows the next tab. Within a second after it, **0** shows the Tricot tab and a number shows that agent, **q** quits (every agent is closed, as closing the window would), **[** scrolls back through the history of an agent that has one, and Ctrl+\\ again sends Ctrl+\\ itself to the agent you were on. A click on the strip picks a tab when the agent showing has the mouse on. Ctrl+Z does nothing here, as an agent stopped in a hidden terminal couldn't be brought back.

Each agent runs in a pseudo-terminal of its own, made with the Perl that ships with macOS (then Python's `pty`, then the `script` command), so nothing is installed. Hidden agents keep running and get their startup questions answered; your terminal's input settings follow the agent showing, and a resize reaches all of them. Claude Code runs in its full-screen renderer here. When you quit, the terminal is put back, the board stops if this command started it and no other agent command needs it (as above), and the command returns the first exit code other than 0, in the order the agents were named and then added (an agent still running when you quit, or stopped from the Tricot tab, was closed, not failed).

To answer from its tab, the terminal is let in once, as a browser is (see [Browsers and terminals you let in](configuration.md#browsers-and-terminals-you-let-in)). Until then the tab shows that an agent is waiting, but not what it asks, and **y** asks to let the terminal answer: your browser shows "Let this terminal answer for you?" with the code the tab shows, and one click there lets it in until it closes. The tab registers with the running board as it starts, and makes the key it signs with; it keeps both in memory only (never in a file, an environment variable or an argument, so the agents it starts never see them) and lets go of them as it ends. When a browser asks to act for you, the tab asks too: "A browser wants to act for you (Chrome on macOS, code 4271). Allow? [y/N]". **y** allows it, **n** or Enter denies it, Esc leaves it for the board; while no browser has ever been let in, any Tricot terminal answers it, once, and is let in with it.

It needs a terminal, and doesn't work on Windows yet.

One agent runs this way too: `tricot claude` shows Claude Code with the strip at the bottom and the Tricot tab beside it, so the process view is there with one agent as with several. `--name` and words after `--` name one agent, so they work with one (`tricot claude --name Reviewer -- --model opus`), and are refused with several. Where the strip can't run (Windows, no terminal, or no way to give the agent a terminal of its own), one agent runs on its own in this terminal, as [above](#starting-an-agent-with-the-board), and says why when your terminal could have had it; several agents are refused there. Gemini CLI can't be started this way either, as above.

## Connecting an agent

`tricot connect claude` connects Claude Code, and `codex`, `pi` and `gemini` connect theirs: Tricot shows the agent's own command, says which of its settings it changes (a server named `tricot`, in `~/.claude.json`, `~/.codex/config.toml`, `~/.pi/agent/mcp.json` or `~/.gemini/settings.json`, for every session), asks whether to run it (`[y/N]`), runs it, and says whether it worked. If the agent refuses, its own message is shown and the exit code is 1; when it already has a `tricot` server, Tricot says so and how to take it out first (`claude mcp remove tricot`). `--yes` skips the question and still shows the command.

`--print` shows the command and runs nothing: for scripts, and for an agent that isn't installed on this computer. Tricot runs nothing either, and prints the command the same way, when there is no terminal to ask in and no `--yes`, or when the agent isn't on your `PATH`, and says what to do. It runs the command without a shell, with 30 seconds to finish. `omp`, `opencode`, `mcp-json` and `url` are a file to edit or an address, so `tricot connect` only shows those. `tricot connect` alone lists every way.

The same by hand, for Claude Code (or any MCP client that speaks Streamable HTTP, by its address):

```sh
claude mcp add --scope user --transport http tricot http://127.0.0.1:4545/mcp
```

Without `--scope user`, Claude Code keeps the server for the one folder you ran the command in.

Add `?agent=Name` to the URL to label an agent on the board, e.g. when several agents share one board. Without it, the MCP client's own name is used.

## Live steps

The first `tricot` in a terminal finds the agents on your machine (Claude Code, Codex, Pi, OMP, Gemini CLI, OpenCode) and asks once whether to show their steps live on your boards ("Reading src/app.ts", "Running npm test" on the card each one works on). It lists the files it would write for each agent; a yes adds a small hook to each agent's own settings, for every project, and a no is remembered too (in the data folder), so it isn't asked again. It never asks without a terminal, in CI, or with `--no-ask`; `--verbose` shows every line first. `tricot steps` shows where each agent stands, and `tricot steps on|off [--agent claude|codex|pi|omp|gemini|opencode]` turns them on or off later, again showing the lines and asking first (`--yes` skips the question). Each agent's panel in Tricot has the same as a "Live steps" switch, which shows the exact files and lines before it writes anything; agents can't turn it on or off themselves. Codex runs a new hook only once you trust it in its `/hooks`, which Tricot says when it sets it up. None of this touches a project's own settings: a project that still has its own hook, from `tricot steps on --agent claude --project`, keeps it, and each step still shows once (the board keeps one of the two copies).

Live steps also pass on each agent's usage, for the Usage section of its panel, and only as numbers. Claude Code tells its plan usage only to its status line, so turning Claude's live steps on also sets `statusLine` in `~/.claude/settings.json` to Tricot's `tricot-usage.mjs`: it keeps from Claude Code's status-line input only the 5-hour and weekly windows (how much is used, when each resets), the session's cost and how full its context is, sends those to Tricot, then runs your own status line with the same input and prints what it prints. Your own status line is kept in `~/.claude/hooks/tricot-usage.json`, and turning live steps off puts it back exactly (or none, if you had none). If you set a status line yourself later (`/statusline`), Tricot leaves it alone and the panel says plan usage stopped. Codex's hook, at the end of each turn, reads the last 256 KB of Codex's own session file and sends only its plan windows, plan and token totals. Pi, OMP and OpenCode send their session's tokens and cost at the end of each turn; Gemini CLI shares nothing Tricot can reach. Nothing reads a login or asks a usage API, and Tricot keeps the numbers in memory only. To stop it, turn live steps off for that agent (`tricot steps off --agent claude`, or the switch in its panel).

With live steps on, Claude Code's and Codex's permission prompts come to the board too: when one asks to run something, its request waits on the card it is working on, as a toast wherever you are in Tricot, and on the chat bar, with Allow, Allow for this session (Claude Code only) and Deny, where you can say why for the agent to read. Allow for this session also allows what Claude Code suggested with the request, for the rest of the session, and the card lists each rule, mode and folder that adds; it is offered only when the card can list all of them in full. What it asks to run shows exactly as it sent it. A background tab says so in its title ("⏸ Claude needs you"), with a system notification if you turned them on. A small hook, `tricot-approve.mjs`, beside the steps hook, sends the request to Tricot and waits for your answer, for as long as you take; it never answers on its own, and when Tricot isn't running (it tries once more, so the terminal asks within a second) or anything goes wrong, the agent asks in the terminal as usual. It believes only the Tricot that holds your data folder (`~/.tricot`, or `TRICOT_DATA_DIR` in the agent's environment): each start of Tricot writes a random secret in its `server.lock`, which only your account can read, and the hook sends a fresh random challenge with everything it asks and prints an answer only when the board proves it holds that secret (an HMAC of the challenge, the request and the answer). Another program that takes the port while Tricot restarts has no secret, so it gets no answer through and never sees what the agent asked to run; a Tricot from before this check, which writes no secret, and a board on another computer, where the hook has no lock to read, make the terminal ask. It works the same on Windows, which has no `lsof`. A program running as you can read the secret too, so this stops a stand-in server, not a determined one. If the agent stops waiting (the prompt answered in the terminal, or the session ended), the request leaves the board. Only a person answers, from a browser or Tricot terminal they let in, on this computer: no MCP tool can, and a page that isn't let in sees who waits, not what they ask. Turning live steps off takes the approval hook out with the rest.

`tricot steps on --agent claude --project`, run in a project, offers to add a Claude Code hook to its `.claude/settings.json` (it shows the JSON and asks first): the card Claude works on then shows what it is doing, one line per step ("Running npm test"), and a command or subagent that takes a while stays live until it ends ("Ran npm test (42 s)"). The same line shows under a message you're waiting on Claude to answer, and on the project's row on the home page. The hook sends no file contents or command output, runs in the background and does nothing when Tricot isn't running. With `--narration` it also sends the first line of each message Claude writes in the terminal (never its thinking); that is off unless you ask for it. `tricot steps off --agent claude --project` takes it out again.

## Updating and removing it

The same `npm install -g tricot` updates it (`brew upgrade tricotstudio/tap/tricot` with Homebrew), and `npm uninstall -g tricot` removes the command; your boards stay in `~/.tricot` either way. To try it once without installing, `npx tricot` runs the same command.
